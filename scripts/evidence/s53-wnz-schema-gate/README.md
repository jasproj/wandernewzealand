# s53 — JSON-LD Offer 3-state unit gate (network ruling s52, ref wanderhawaii #263)

Base `origin/main` `03a045981964e48a0e5c23ce336891cc1e21e506` == local `main` at gate 0.

## Recon — every path that writes offers into JSON-LD

`grep -rln '"Offer"\|TouristTrip\|UnitPriceSpecification\|priceCurrency'` over every `.js`/`.astro`/`.html` in
the repo (excluding `node_modules`) turns up exactly one hit: `app.js`. `generateTourSchema(tour)` is called
from exactly one place, `createTourCard(tour)`, which is the only caller in the tree (`grep -rln
generateTourSchema` also returns only `app.js`). No HTML page embeds a tour `Offer` inline — the only other
`application/ld+json` blocks in tracked HTML are page-level `FAQPage` schema (e.g. `tours.html:550`), unrelated
to tour pricing. **One emitter. Fixed once, fixed everywhere** — unlike a two-emitter site, there is no second
path to half-fix.

## Pre-existing gate

`app.js` `generateTourSchema()` (pre-s53): `emitPrice = Number.isFinite(tour.price) && priceConfidence !==
'low' && currency ∈ {NZD, USD}` (the `CURRENCY_SYMBOL` map from s48). Any row clearing that gate got a bare
`Offer.price` — no unit check at all. The card's own unit badge, `priceUnit(tour)` (s45, ported from KWST),
reads **only** the explicit `_unknownFields.priceUnit` field — no inference — and renders it as `<small>` after
the price text. That explicit-only card path is untouched by this change; s52 authorizes inference **only** for
the JSON-LD unit-state classification, not for the wording the card (or `unitText`) shows.

## Measurement — before touching anything

Render-eligible population (`status !== 'inactive' && !bookingDead`, same predicate as `app.js:140`): **3111**
of 3121 tours. Offer-emission gate on that population: **2001** rows (`state-census.json` /
`gate-diff.json`, `before.bareOffer`). This matches the s48 evidence figure (2001) — confirms the population is
stable since the last currency-gate measurement.

`_unknownFields.priceUnit` — the field the card mirrors — is populated on **1 row in the entire 3121-row
dataset** (pk 489299, stamped by s45), and that row is inside the 2001-row emitting population. So of any rows
this gate reclassifies as non-per-person, at most 1 can carry a mirrorable unit; every other non-per-person row
has no card wording to mirror and must go silent, per the ruling ("a row with no mirrorable card unit emits no
price at all").

## Unit-state classification (`vocab.json`, `price-labels-census.json`)

Evidence derived from **this pool's own `priceLabel` vocabulary** — 425 distinct labels across the 2001-row
emitting population (`price-labels-census.json`, generated by `gate-harness.mjs` from live `tours-data.json`,
not hand-typed). Four word lists, checked in order, each mined from labels actually present in this pool
(`vocab.json` has full source + rationale + real examples per bucket):

1. **multiCount** — explicit ≥2 count + person/pax noun ("Group of 2", "Two people", "Adult (2 Pax)") → non-per-person.
2. **group** — family/group/team/shared/twin/double/triple/couple/party/seater/charter wording, "up to N", or
   "private tour/event/transport" ("Friends & Family", "Three Seater", "MD520N Helicopter for up to 3 pax") →
   non-per-person.
3. **person** — an unmodified single-person noun with neither override ahead of it ("Adult", "Person",
   "Passenger", "Adult with Bike") → per-person.
4. **equipment** — vehicle/gear/site-night rental wording with no person or group signal ("One Day Hire", "XS
   Bike", "Executive Sedan", "Dog Day Pass") → non-per-person.
5. Anything matching none of the above → **unknown** — no price key. This is the deliberate, honest bucket:
   duration-only or one-off descriptive labels ("Half Day", "Auckland City Tour - 7.5 Hours", "Private Lesson",
   "Session", "Bag") give this pool no way to tell person-price from item-price, so the row emits nothing rather
   than guess.

The same four regex sources live in `app.js` (`MULTI_COUNT_UNIT_RE` / `GROUP_UNIT_RE` / `PERSON_UNIT_RE` /
`EQUIPMENT_UNIT_RE`, next to `classifyPriceUnit`) — copy-identical to `vocab.json`'s `source` fields. `app.js`
is a plain non-module script (`<script src="app.js">`, no bundler), so the two copies are kept in sync by
construction rather than by import; `gate-harness.mjs` loads `vocab.json` independently of `app.js` and its
output (below) is generated by *running* `app.js`'s real `generateTourSchema`, not by re-implementing it, so a
drift between the two copies would show up as a harness assertion failure, not a silent mismatch.

`unitText`.

## Proof both directions (`fixtures.json`, `gate-diff.json`)

Four real rows from this repo's own `tours-data.json`, run through the actual (unmodified) `generateTourSchema`
before and after the change (`gate-harness.mjs` evaluates both `git show HEAD:app.js` and the working-tree
`app.js` in a node `vm`, over the same data):

- **pk 171361** "Bushwalk & Snack Run", `priceLabel: "Adult"` → per-person. `beforeOffers` and `afterOffers`
  are the identical `{"@type":"Offer","price":120,"priceCurrency":"NZD",...}` object
  (`gate-diff.json.perPersonByteIdentical: true`, asserted over all 1289 per-person rows, not just this one).
- **pk 489299** "Skippers Canyon Bespoke Tour", `priceLabel: "Private Charter"` → non-per-person, and the one
  row with a mirrorable `_unknownFields.priceUnit` ("whole vehicle · up to 4 people"). Before: bare
  `price: 1262.61`. After: no bare `price` key; `priceSpecification: {"@type":"UnitPriceSpecification",
  "price":1262.61,"priceCurrency":"NZD","unitText":"whole vehicle · up to 4 people"}` — `unitText` is exactly
  the string `priceUnit()` renders on the card, not a paraphrase.
- **pk 649402** "Mountain Explorer - Ride Along Buggy Tour", `priceLabel: "Scenic Tour - Honda Pioneer (up to 5
  passengers)"` → non-per-person, no `_unknownFields.priceUnit`. Before: bare `price: 798`. After:
  `afterOffers: null` — no `offers` key at all (`schema.offers` absent from the JSON-LD block).
- **pk 254542** "Double Kayak Hire", `priceLabel: "Half Day"` → no unit evidence either way (note: the *tour
  name* mentions a kayak, but classification runs on `priceLabel`, not name — "Half Day" alone asserts nothing
  about person-vs-item). Before: bare `price: 83.74`. After: `afterOffers: null`.

`gate-diff.json` asserts the last two behaviors over the *whole* population, not just these examples:
`nonPerPersonNeverBareAfter: true` (none of the 557 non-per-person rows emit a bare price after the change) and
`unknownNeverEmitsAfter: true` (none of the 155 unknown rows emit any offer after the change).
